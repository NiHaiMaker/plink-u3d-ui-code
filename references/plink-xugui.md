# PLink / XUGUI 接入

仅在目标项目实际使用 PLink/XUGUI 时读取。本文件提供接入顺序，具体 API 与代码所有权以目标项目当前规范和源码为准，不复制某个项目的面板、资源或版本状态。策划案与已生成的 Prefab 先用于只读任务拆解；下述资产修改、生成和手写实现只在用户确认对应 task 后执行。

## 项目规范路由

1. 先执行仓库入口规定的 `.cursor/` 枚举与按需读取，遵守 `.cursor/rules/read-exclusions.mdc`、`ai-workflow.mdc` 和项目 SSOT 优先级。
2. 完整读取目标项目存在的 `.cursor/skills/plink-ui-panels/SKILL.md`、`reference.md`、`examples.md`。
3. 编写 PLink 手写代码前，读取 `plink-framework` 及其配套资料和 C# 命名/类布局规则；涉及 PSD 处理时才读取项目 PSD 技能与用户指定的 PSD 工作流。
4. 从源码确认生成器、Item 克隆/回收、事件 API 与安装的可选扩展；缺少 Skill 或能力时不能按历史接口猜测。
5. 本 Skill 的运行时禁令是用户对本轮 UI 实现的限制。其他 Skill 中的运行时补组件、动态查找、临时创建节点等示例，不因此成为获准方案。

## 业务与框架归属

- 先从目标项目当前规范和调用链确认所有权。`client/Assets/A_PLink_Public/` 中的 Core、Module、公共 Function、XUGUI 运行时和生成器通常属于框架；`client/Assets/AZ_RProject/` 中的具体面板 Entity/Item、项目数据适配和功能逻辑通常属于业务，但其中的公共基类/通用设施仍可能属于框架。路径和 `R` 前缀仅作线索，不能单独定性。
- `UIManagerEntity`、`UIBaseEntity`、`UIPanelBaseItem`、公共监听器/Extension、对象池、资源加载机制、`UIPrefabOperationEditor` 等基础能力，默认只读复用。给当前面板解决问题不能擅自修改这些类型、默认行为、公共 API 或生成模板。
- 在既有业务 Entity/Item 中实现展示与交互，通过已存在的扩展点适配业务，属于业务修改；直接改公共基类、全局行为、框架分发或所有面板共用的逻辑，属于框架修改，即使文件放在项目目录也不例外。
- 用已有生成器生成获准面板的业务绑定，不等于修改框架；改生成器实现、命名协议、公共模板或组件支持范围，则需要明确的框架修改授权。禁止手改生成物的约定仍然有效。
- 缺少框架能力或发现框架问题时，报告具体证据和受影响 task；先检查是否有符合现有契约的业务层方案。不得为当前面板增设另一套公共框架，也不得复制框架到业务目录后修改来规避授权。
- 任务拆解不改变已有代码文件组织。未经明确同意，不将面板 Entity/Item 手写代码拆成 `.Storage.cs`、`.Events.cs`、`.Binding.cs` 等职责分文件；可以按职责修改已有手写 partial。既有生成/手写分离继续遵守，不自行合并或迁移。

## 固定配置与绑定

- 按现有命名协议使用 `_g`、`_b`、`_c`、`_@` 终止后缀，核对同一生成作用域内名称唯一、标识合法和组件支持范围。
- `_@` 建立 Item 边界，使用生成的 `Clone_*` 入口复制完整模板；以当前代码确认其参数、父节点和绑定时机。
- `_b` 常对应 `UIEventTriggerListener`，不能当作 `UnityEngine.UI.Button`；`_c` 只支持生成器明确识别的组件，不能猜测绑定类型。
- `_b` 按钮节点自身配置射线接收 Graphic，并在编辑期启用其 `raycastTarget`；监听器和射线组件位于同一按钮对象。已有合适的 Image/Graphic 时直接复用，不重复叠加。缺少可见背景时，按项目已有透明射线 Graphic 方案在编辑期配置，不改成让装饰文字/图标承担按钮本体射线。纯装饰子节点的 `raycastTarget` 按需关闭，保留独立交互子节点的职责。
- 能通过生成协议取得的字段必须使用生成引用。缺少引用回到 Prefab/生成链修正，不在手写代码中使用 `Transform.Find`、字符串路径或 `GetComponent` 代替生成字段。
- `UIEventTriggerListener.Get` 一类方法可能在组件缺失时执行 `AddComponent`。运行时手写代码不调用这类补建入口；在编辑期由权威工具配置好监听器，再使用序列化字段。
- 编辑期调用补组件工具与运行时调用性质不同；必须确认执行时机、最终保存的 Prefab 组件和序列化引用，不能只看方法名就判违规或判安全。

## 生成文件与执行顺序

- 检查生成器实际创建、覆盖、删除哪些文件。`*_Mono.cs` 即使没有 `_Auto` 后缀，也可能是生成物。
- 自动文件由工具生成；UI 手写逻辑进入不会被覆盖的已有 `*Entity.cs` / Item partial。需要序列化字段时优先使用既有合法手写扩展文件；确需新增 `.Config.cs` 等职责分文件，先说明与生成物隔离的必要性并取得用户明确同意，不能改生成文件规避确认。权威工具按既有协议创建必要的自动/手写配套文件可随已确认的生成任务执行，不等于授权额外拆分业务实现。
- 已有 Prefab 和绑定完整时直接复用。只有已确认的 task 需要更改组件或绑定时，才执行：编辑期修正 Prefab → 代码生成 → 修复本 task 确认失效的手写引用/类型 → 编译与类型加载成功 → 刷新 Prefab → 检查绑定。
- 不把“刷新”假定为纯引用回写：执行前核对它是否还会覆盖代码、补组件、重设根配置或删除自动文件。
- 生成/刷新后必须重新检查当前 task 的布局和样式；若生成器改回了用户配置，按项目权威编辑流程修正资产并复验，不能在 `OnShow` 中反向补偿。

## 手写代码边界

- UI Entity 管展示和生命周期，调用方拥有业务流程。用户只要求完成回调时，保留调用方钩子，不自动跳转场景、打开下一面板或启动玩法。
- UI 不直接修改外部业务字段、集合或回收业务对象，通过其所属逻辑实体/管理器公开方法提交意图。
- 项目启用 XUGUI Extension 与 DOTween 时，遵守项目要求的 `AddClickListener` 接口，使用按钮本体的已有生成 Listener，并成对解绑。注册附带的点击动画应作用于同一按钮 Transform，使背景和装饰内容随按钮整体反馈；核对实际扩展实现，不把 Listener 绑到装饰子节点。沿用项目已确认的点击效果，不为绕过运行时固定配置约束而禁用正常的注册动画，也不另写样式补偿、重复动画或运行时补组件逻辑。
- 先沿现有注册/动画调用链确认按钮实际目标；若框架使用独立动画目标或注册路径确实会运行时补组件，报告具体冲突和受影响 task，不擅自修改框架，也不把“注册附带动画”解释为允许添加组件。
- 字段清理、`base.Dispose()` / `base.Push()` 顺序、对象获取和日志 API 遵循 `plink-framework`，不另建调度或对象池。
- 检查 `_@` Item 的 `Push()` 是否只回收包装对象。按现有所有权处理实例 GameObject，不把“对象已回池”误报为“UI 已移除”。
- 既有 UIManager/布局/动画可能有运行时配置行为：如与本轮要求直接冲突，指出具体调用链和影响，在方案中解决；不能静默忽略，也不因本 Skill 自动扩大到全框架重构。

## Unity 验证

项目规定 Unity 操作只能使用 Coplay MCP 时，遵守该工具边界；工具异常按项目规则核对/重试，仍失败则报告具体阻塞项，不换通道绕过。源码和文档读写仍按仓库常规工具执行。

不得自动修改 Enter Play Mode Options、Reload Domain、Reload Scene。生成文件和 Prefab 的静态证据不能替代编译、类型加载与 PlayMode 结果。

检查 `_@` 模板与实例组件一致、重复刷新不重复订阅、隐藏重开不残留监听、增减 Item 不泄漏，并确认本轮没有在运行时覆盖字号或布局配置。

按钮额外检查：射线 Graphic 与生成 Listener 是否都在按钮本体；点击背景、文字和图标区域能否按预期触发同一按钮；按下时是否由正确的按钮对象带动整体点击反馈，是否存在装饰节点拦截或重复触发。未执行 Unity 操作时只能报告静态配置检查结果。
